# morning-brief

生成当日盘前简报。

本技能版本：morning-brief-v1。

## 流程

1. **先查交易日**：`get_market_data_status`。非交易日就静默退出，只回一句「今天不是交易日」，不产出简报、不写库。
2. 读事实（全部来自工具，不要凭记忆）：
   - `list_holdings`：持仓、成本、市值、浮盈；
   - `list_watch_triggers`：盯盘触发与命中情况；
   - `get_advice`：既有建议（含反证、风险、免责声明、有效期）；
   - `list_watchlists`：关注列表；
   - `list_strategies` 与 `get_watch_status`：策略状态与盯盘健康度。
3. 输出简报，固定四段：
   - **账户概览**：资产、持仓数、今日盈亏（标明 `dataAsOf`）；
   - **隔夜与盘前要闻**：只写事实包里有的东西，没有就写「无新增」；
   - **既有建议与反证**：保留原建议的决策、信心度、证据、反证、风险、免责声明、有效期；
   - **今日关注计划**：观察条件（价位、量能、失效条件），不给买卖指令。
4. 用 `present` 把简报作为交付物呈现给用户。

## 写回路径

- 盘前简报是**会话交付物**，不写 luoome 事实库：插件形态没有报告写回工具，把简报塞进 Advice 或
  DecisionReview 等于伪造投研事实，也是把「提示」当「记录」。
- 写回路径只有一条：`present` 交付到当前会话的交付物目录（文件名 `<YYYY-MM-DD>-morning-brief.md`）。
- 用户要求长期留档时，先确认他要的是「笔记」还是「决策」：要笔记就用 `save_decision_review` 的
  `content.note` 显式记录（并说明这是用户笔记，不是 AI 简报）；只要简报就停在交付物，不落库。

## 边界

- 建议不等于成交，不得出现「买入/卖出/已建仓」这类表述。
- 先给反面证据，再给结论，最后给可证伪的观察条件。
- 数字必须与工具输出逐位一致；取不到的数字直说取不到，不要估算。
- 区分 `StrategySignal`、`Advice` 与成交记录，不要把信号说成建议。
