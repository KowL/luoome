### W01–W03：先交付可运行的首页旅程

- 复用现有行情、账户、计划、提醒和报告，不使用预置推荐冒充 AI 结果。
- 输入入口与卡片共享会话，关闭讨论不取消既有跟踪。
- 服务端解析真实主体；客户端不能提交伪造的助手消息或执行结果。
- 手机覆盖 360/390/430px、桌面布局；实际启动浏览器验证，模拟视口不宣称真机验收。

### W04–W06：方向与共识形成可用业务能力

- 先写清最小契约，复用 Advice/TradingPlan，不复制逐股仓位和退出规则。
- 方向、已确认共识、用户临时意愿、执行状态分开；确认方向不等于买入。
- schema、双仓储、幂等迁移、tools、权限白名单、workflow 与测试同步。
- 提案引用可用事实；缺数据时限制结论，模型失败不产出伪研究。
- UI 所需的工具名、请求、输出、状态与错误示例先发布在 B 的交接文件，冻结后不随意更改。

### W07–W08：后台和实际行动闭环

- 优先检查已存在的 email 通知偏好和 SMTP 基础，允许实现可配置邮件通知传输作为工程入口；不声称用户已选择最终手机通知渠道。
- 不读取或输出真实密钥，不连接生产私人账户，不擅自发送真实外部消息；用注入 transport 和隔离测试验证。
- SMTP 受理不等于手机到达；不伪造 provider 幂等支持、到达回执或查询结果。
- 复用当前 worker、通知意图与成交登记；不得重复实现一套任务或账本系统。
- 真实渠道配置、手机到达与真机测试列出未验收条件，其它实现继续推进。

## 2. 共享工作目录的修改边界

多个线程不同时编辑同一个文件，不切分支、不建未经请求的 worktree、不执行仓库级自动格式化。
先阅读当前 git diff 区分此前改动与本线程改动，测试失败不得直接改动其它线程正在写的模块。

| 线程 | 独占写入范围 | 不直接修改 |
|---|---|---|
| A：首页、对话与最终接入 | `apps/web/public/`，`apps/web/src/chat.ts`、`server.ts` 及对应测试；其余 Web 路由变更；新功能总 DDD；最终用户手册/导航更新 | B 的领域/仓储/tools/workflows，C 的通知/装配文件，除非交接已明确释放 |
| B：方向、共识与记忆 | `packages/core/src/entity/` 与 repository 接口；`packages/db/src/repository/`、schema/client；新增方向/共识 tools、相关 agent 场景、registry/barrel、WorkflowToolMap；新增相关 workflow；对应测试、CONTEXT 和 Skill 能力分类 | Web 文件、C 的 `core/hosted` 通知模型、`tools/platform` 通知和已有通知投递模块 |
| C：后台跟踪与通知 | `packages/adapters/src/hosted/` 通知实现和测试；`apps/web/src/hosted-providers.ts`/config 与对应测试；`apps/worker/`、托管通知/跟踪模块与相邻测试；必要的 `core/hosted` 通知模型 | `server.ts`、`chat.ts`、前端、B 的共享 registry/barrel/schema 与新方向实体 |

需要超出范围时，把请求和准确修改建议写入自己的交接文件，由 A 在文件所有者释放后实施；不能先改再报告。
B/C 交接完成后不再修改已释放文件；若仍需改动，将状态重新设为进行中并避免 A 同时接入。
共享导出和 WorkflowToolMap 由 B 在自己的阶段统一修改；C 可列出所需导出，A 在 B 完成后补齐。
A 不提前猜测 B 的业务契约，也不为等待契约创建另一套临时领域模型。

## 3. 交接与持续执行

各线程开始时创建自己的交接文件，原子更新或小范围修改；文件是当前任务协作记录，`output/` 已被 Git 忽略。

| 线程 | 交接文件 | 最低内容 |
|---|---|---|
| A | `output/ai-investment-workspace/A-handoff.md` | 阶段、接口消费情况、浏览器与自动测试、未验收项 |
| B | `output/ai-investment-workspace/B-handoff.md` | 状态、冻结契约、工具/API 示例、已有代码与测试、释放文件 |
| C | `output/ai-investment-workspace/C-handoff.md` | 状态、配置及恢复行为、深链接契约、测试、外部前置条件、释放文件 |

状态使用 `implementing / contract-ready / ready-for-integration / complete / external-validation-pending`，区分实现完成和真实外部验收。
`ready-for-integration` 必须附接口和相关测试结果。仅有设计或空壳文件不算完成。
A 可以通过线程状态工具读取 B/C 的进度，在独立首页工作完成后接入已就绪实现，再做整体检查。
各线程不得创建更多线程或向其它线程发送消息；使用上述交接文件和只读线程状态协调。
需要用户决定的外部事项明确记录，继续不依赖该决定的工作，不擅自假定真实通知已获发送授权。
