## 1. 背景与目标

托管版已完成登录、订阅、默认账户接线，管理后台（admin-console-v1）开发中。
但付费承诺「每天自动服务」尚未兑现：预警、报告、Strategy 日循环仍依赖单机调度或手动触发，
统一登录 Web 不再启动单机调度器，按用户自动调度待接入独立 worker（见 CONTEXT.md StrategySchedule）。
真实 LLM provider 未接入，49 元/月的 AI 成本假设未验证。

本版目标（两周）：

1. **兑现自动触达**：预警链与开盘/收盘报告按租户自动运行并真实投递。
2. **补证据链**：Strategy 日循环 + T+1/T+3/T+5 观察补全在托管 worker 下运行；
   收盘报告嵌入建议校准摘要。
3. **成本闭环**：接入一个真实 LLM provider，额度预占/结算可恢复，
   产出真实每户成本分布与 49 元套餐成本试算。

排序依据：预警（「有事叫我」）是付费第一动机；报告（「每天看我一眼」）是每日触达与续费理由
（见 subscription-pricing-v1 §3.1）；TradingPlan/AccountFacts 扩展因录账门槛高、转化慢，缓做。

## 2. 范围与任务拆分

| ID | 任务 | 改动范围 | 验收标准 | 依赖 |
|---|---|---|---|---|
| DS-1 | 行情请求总量约束与降级契约 | 公共行情缓存边界、跨 Web/worker 请求合并、provider 总限速、不可用降级、预警扫描批次计量 | 邀请规模混合负载下请求量不突破配置上限；429/断网注入后降级返回 stale/unavailable，不穿透放大上游请求 | — |
| DS-2 | 预警链 worker 化 | 按租户执行 AlertPlan 规则评估、边沿状态、WatchTrigger 持久化、真实通知投递（飞书/日志 fallback） | 新用户 5 分钟完成模板→试跑→启用；并发与重启不串租户、不重复触发；渠道 accepted 不冒充 delivered；订阅到期阻断待发提醒 | DS-1 |
| DS-3 | 报告 worker 化 | 开盘简报/收盘复盘按租户定时生成与投递；收盘报告等待当日预期策略与交易计划批次完成，同日同范围只生成一份 | 18:00 未完成继续等待，不提前发布缺口版；重复生成与投递重试复用原报告；投递受理/未知/送达分别记录 | DS-1 |
| DS-4 | 故障注入验收 | DS-1～DS-3 的故障注入测试套件 | 注入 429、断网、进程重启：无串租户、无重复触发、无重复扣额；陈旧行情阻断动作提醒 | DS-2、DS-3 |
| DS-5 | Strategy 日循环 worker 接入 | 盘后 daily cycle（调度、数据准备、正式运行、观察补全）按租户在 worker 运行；T+1/T+3/T+5 观察补全 | 失败不覆盖已发布结果；版本→信号→观察可追溯；facts-only 降级保留截止时间、缺失率 | DS-1 |
| DS-6 | 收盘报告校准摘要 | 收盘复盘报告固定嵌入「近期建议校准摘要」，复用既有 DecisionReview 统计 | 摘要与既有统计口径一致；必须披露账户范围、反馈覆盖率、样本量；无样本明确提示；不把填报盈利占比表述为收益率或预测准确率 | DS-3 |
| DS-7 | 真实 LLM 接入与成本闭环 | 接入一个真实 LLM provider；调用/重试/修复的额度预占与结算；成本统计 | 模型超时、预算耗尽、跨服务期重试可恢复、不重复扣额；产出真实每户成本分布与 49 元套餐成本试算；未装配时明确不可用，不返回 mock | DS-5 |

任务粒度说明：DS-1 是其它全部任务的前置（总量约束未定义前，worker 化会放大上游封禁风险）。
DS-2 与 DS-3 可并行。浏览器验收（完整用户旅程）在 DS-4 之后统一进行。

## 3. 领域与架构约束（不可违反）

- 预警、报告、Strategy 的事实语义以 CONTEXT.md 为准：Trigger 含规则/方向/证据/数据时间/送达状态；
  报告保存结构化事实与数据截止时间，Markdown 只是派生展示；`complete` 只表达执行终态。
- 投递语义：`DeliveryIntent` 的 accepted 只表示渠道受理，delivered 需要可信回执；
  暂停、成员退出、偏好撤销、到期、删除都阻止尚未发送的失效提醒。
- 校准摘要只消费当前账户的明确反馈；盈亏未知保持缺失；0 仅表示用户明确填报的零盈亏。
- Advice 不等于 Trade；任何建议、预警、报告都不会自动下单；trade tool 不通过 MCP 暴露。
- Workflow 只通过 `ctx.tools.*` 编排；新 repository 同时提供 drizzle 与 in-memory 实现并复用 contract tests；
  drizzle schema 与 `ensureSchema` DDL 同步，启动迁移幂等。
- 平台密钥、数据源配置不向租户开放全局写权限；AI 未装配时明确不可用，不返回 mock 结果。

## 4. 明确不做（两周内）

- 报告重设计、复盘仪表盘、新因子 / PIT 基本面评分接入 Strategy DSL、多档套餐与年付、
  管理后台扩建（只做 admin-console-v1 既定范围）、自动下单、新市场（港股/美股/北交所）、
  完整持仓批量导入与本地整库迁云、PostgreSQL/Redis/K8s 扩容（由实测瓶颈决定）。

## 5. 风险

| 风险 | 缓解 |
|---|---|
| 多租户共用东财/腾讯/新浪抓取链路触发上游封禁 | DS-1 总量约束 + 降级契约 + DS-4 故障注入验收先行 |
| 额度与任务粒度错配（盘中扫描挤掉报告/研究） | DS-1 定义批次计量与任务优先级；DS-7 以混合负载验证 |
| 49 元定价的 AI 成本假设未验证 | DS-7 产出真实每户成本分布与套餐成本试算，不达标则调整额度而非降价 |
| worker 化改动与进行中的 admin-console-v1 工作树冲突 | 任务按文件边界串行派工；不 revert 未提交改动 |
