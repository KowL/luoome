# 个人订阅托管版开发改造计划

> **已归档（2026-10-23）**：本文描述的是已下线的多租户托管形态，当前形态是单机版（见 docs/ddd/luoome-dsh-transformation-detailed-design.md 的 D9–D12）。仅作历史留存，不是当前行为说明。

> 状态：原 Web 登录融合、默认账户及订阅/通知设置已实现并完成本轮隔离验证；后台自动调度、原业务通知投递、统一计量与真实 provider 接入仍待完成。
> 更新：2026-10-13；原设计日期：2026-10-10。
> 契约：[个人订阅托管版详细设计](./hosted-personal-subscription-detailed-design.md)。
> 领域约束：[CONTEXT](../../CONTEXT.md)、[架构](../ARCHITECTURE.md)、[安全](../SECURITY.md)。

## 1. 已确认范围

**保留现有 Web 和已实现业务，在其上增加登录、用户隔离与支付订阅。** 不重写页面，不另建精简事实版，
不把自选、Strategy、通知、报告、复盘、持仓、研究或 AI 对话列为将来才恢复的功能。

每个托管用户自动拥有一个默认投资账户，不提供新增或切换多账户；允许编辑账户名称。
服务身份 User、隔离边界 Tenant 与投资 Account 仍分别建模，local 模式保持原有多账户行为。

本计划替代此前 `hosted-facts-v1`、无 Account、独立“今日变化/我的提醒”应用和分阶段恢复原业务的范围。
旧事实方案已经产生的代码和 fixture 证据可以复用，但不能据此宣称本版原页面与完整业务已验收。

### 1.1 保留与新增

| 范围 | 本次处理 |
|---|---|
| 原业务首页、导航与页面 | 复用 `apps/web/public/index.html` 与现有 JS/CSS，不重新设计替代页面 |
| 自选、Strategy、AlertPlan、通知、报告、复盘 | 保留既有功能、来源关系、规则类型和业务语义，补齐每用户上下文 |
| 持仓、资金、手工成交、绩效、Advice、交易计划 | 使用该用户默认 Account，保留既有 ledger 与人工确认边界 |
| 研究、AI 对话、SSE、草案确认 | 保留产品入口；补租户隔离、资源预算和真实 provider 装配；未配置明确提示 |
| 登录与订阅 | 新增必要身份/付款页面，个人订阅、订单、用量和退出登录嵌入原设置页 |
| 账户管理 | 自动唯一默认账户、名称编辑；移除托管新增/切换入口并在服务端拒绝绕行 |
| 平台设置与个人偏好 | 个人通知/显示偏好可维护；平台模型密钥、数据源、Vault 路径及整库恢复不向租户开放全局写权限 |

“不对租户开放平台配置”不等于删除依赖该配置的业务。真实 LLM 尚未接入时应显示未配置，
不能返回 mock 建议，也不能把隐藏 AI 页面当作本任务完成。

### 1.2 不增加的范围

本次不增加自动证券交易、远程 MCP、团队/组织、新市场或新的持仓 CSV 解析功能。
完整持仓批量导入与本地整库迁云仍需独立设计；这不影响现有手工持仓和成交功能的保留。
PostgreSQL、Redis、Kubernetes 和多节点扩容由实测瓶颈决定，不作为本次页面融合前置条件。

## 3. 剩余开发顺序

### 3.1 原 Web 请求级融合

目标：用户登录后看到原应用，原业务路由在当前用户的 Tenant 中运行。

- hosted 外壳只负责认证、固定 Origin/CSRF、订阅和生命周期，在通过校验后桥接原 `createWebApp`。
- 复用原 `public/index.html`、导航与模块；保留必要登录资源，不再把旧 hosted 事实页作为登录后首页。
- 为每个请求构造不可变的 Tenant context；业务专用端点、generic Tool、聊天和草案确认均不能退回 local-user 或共享 DB。
- SSE、`onFinish`、后台 job 和其它延迟回调持有 runtime lease 到真正结束；响应头返回不等于执行已结束。
- 原前端登录失效、用户切换与双标签退出清空私人状态；不能复用另一个用户的账户 header、DOM 或异步回调。

验收：DDD A01～A05、A23、A24。真实浏览器验证登录→原看板→自选/Strategy/通知/复盘，
并用两个用户交叉请求同名对象。身份桥接成功不代表全部业务已经接通。

### 3.2 唯一默认投资账户与原复盘

依赖请求隔离及现有租户初始化契约。

- 内部 `ensure_default_account` 在空租户库原子创建 `default-account`、“默认投资账户”、real/CNY、本金0/现金0。
- 已有唯一账户原样复用；已有多账户则停止自动迁移、保留数据并给出核对状态；并发/重试不得重复建账。
- provisioning 完成默认账户初始化后才激活租户；旧无账户托管库补齐同一步骤，不凭空产生入金、持仓或 Trade。
- 服务端绑定 `defaultAccountId`；托管用户不能通过 header、body、generic Tool、AI 草案或遗留端点新增/切换账户。
- 原账户页面/设置仅保留名称编辑，`update_account({accountId?, name})` 严格禁止本金、现金、币种等额外字段。
- 资金变化继续走原现金流水和 ledger 事务；原 Trigger/Advice/计划复盘复用默认账户 DecisionReview。
  旧 PersonalWatchFeedback 只作为历史数据读取/导出，不能静默转成账户采纳或收益事实。

验收：DDD A06、A21、A22；包括双标签首次登录、重复provision、唯一旧账户、异常多账户、
编辑名称后重登、资金字段注入和local多账户回归。0余额只是初始空账本，不等于已核实用户真实资产为零。

### 3.3 现有业务逐链路接线

依赖请求级 context 和唯一默认账户；本阶段属于本次任务，不是未来功能开放。

| 业务链路 | 必须保留与核对 |
|---|---|
| 自选与Strategy | 原版本/发布/运行/信号、Strategy→Watchlist显式订阅、多来源同步；任务结果不串租户 |
| AlertPlan/WatchTrigger/通知 | 原规则集合、试跑/边沿/冷却/当日重试、租户通知目的地；不收窄为仅价格两种规则 |
| 持仓/成交/账户事实 | 绑定默认账户，账本现金/持仓/回执原子提交；不开放券商自动交易 |
| 报告与复盘 | opening/closing/weekly及既有等待/版本语义不变；反馈、成交与事后观察不混算 |
| 研究/Advice/TradingPlan/AI | 原页面和工具契约，反证/风险/有效期保留；SSE、模型工具和确认草案隔离 |
| 历史评估与其它长任务 | 将进程Map和捕获的共享context转为租户绑定的任务身份/状态；原数据门禁不放宽 |

原业务 Tool 仍返回 ToolResult；授权的用途是保护权限、预算及数据归属，不是按旧事实白名单屏蔽本人建议。
真实模型、基本面或行情能力未准备好时保留原不可用状态，不能把测试 provider 当作生产事实。

验收：DDD A05、A08、A09、A21、A24；每条链路必须区分“路由可达”“业务可用”“真实provider已验收”。

### 3.4 原设置页、订阅与个人通知

依赖原页面复用及平台已有支付/权益契约。

- 在原设置页增加账户名称、服务期、订单/用量、续费、个人通知和退出登录，避免另建独立业务设置应用。
- 原平台级AI/行情/Vault/整库配置不直接交给普通租户；需要配置的页面显示当前能力与管理员配置状态。
- 复用不可变 PlanVersion、支付/退款/查单契约；试用或订阅权益覆盖原业务，不能只对旧事实job扣额而漏掉AI/策略。
- 到期保留规定窗口内的历史读取、导出与删除；历史读取不隐式启动模型、刷新行情或策略任务。
- 通知当前用户的绑定、安静时段、额度与accepted/unknown状态继续生效；平台安全邮件与研究订阅分别处理。

验收：DDD A10～A14、A16～A18。旧支付fixture不替代原页面购买→使用原业务→到期→导出旅程，
真实邮件/支付渠道尚未接入部分单列为待验收。

### 3.5 后台调度、真实模型与恢复覆盖

依赖原业务调用链接线和平台任务契约，可与页面增量并行。

- 原Strategy schedule、日循环、账户计划盯盘、绩效快照、报告及观察补全按Tenant运行；保留领域lease/fencing/checkpoint。
- hosted不能在每个Web实例重复启动全租户scheduler；复用独立worker、公平分发、订阅/删除复核与稳定operation身份。
- AI真实provider装配、SSE/agent预算和每次重试/修复的成本计量属于保留AI功能的必要实现；未接入时明确不可用。
- Job、用户额度、provider成本与通知分别记录；不能因为原页面已能调用就跳过预占、原期段结算或unknown处理。
- 新业务执行/SSE/缓存写入一并纳入删除排空与备份屏障；恢复时对账，不盲目重放原策略、成交或邮件。

验收：DDD A12～A20、A24，含kill/restart、同一租户重任务与其它租户并发、SSE断开、到期/删除竞态。
当前自动调度和真实AI接线尚不能凭旧事实workflow测试标记为完成；逐项保留实际证据。

### 3.6 本版浏览器、回归与生产门禁

只有上述链路及受影响自动测试完成后，才做本版端到端验收：

1. 新用户登录即进入原Web；自动一个默认账户，无新增/切换；修改名称重登保持。
2. 原自选/策略/通知/报告/复盘可正常操作；所有原页面保留，缺provider准确解释。
3. 两用户并发、双标签/SSE和worker不串数据；订阅约束也覆盖模型子工具与后台任务。
4. 默认账户下账本/反馈/成交关联保持原子；local多账户、MCP trade硬卡回归。
5. 原设置页购买、续费、到期、通知、导出、删除一致；真实供应商与fixture分别列结果。

数据商用许可、实际业务评估、正式条款/同意、真实支付邮件、生产模型及监控恢复仍是相应上线门禁。
未通过时不开放生产注册/收费，但不能把这些门禁改写为删除用户已经确认的功能。

- 实现先读目标及相邻测试；新增schema/repository同步Drizzle、memory、ensureSchema与contract tests。
