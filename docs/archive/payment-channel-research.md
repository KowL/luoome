# 支付渠道接入调研

> **已归档（2026-10-23）**：本文描述的是已下线的多租户托管形态，当前形态是单机版（见 docs/ddd/luoome-dsh-transformation-detailed-design.md 的 D9–D12）。仅作历史留存，不是当前行为说明。

> 状态：调研完成，待决策；2026-10-14。
> 关联：[订阅定价与套餐设计 v1](./subscription-pricing-v1.md)、[运行手册](./hosted-personal-subscription-runbook.md)。
> 结论先行：**注册个体工商户 → 域名 ICP 备案 + HTTPS → 微信支付 Native（扫码）+ 支付宝电脑网站支付双渠道直连**是唯一长期路径；个人收款码和服务商二级商户只适合过渡且有明确风险。

## 1. 代码侧现状：契约已就绪，只缺 provider 实现

支付能力在架构上是显式可插拔的 `HostedPaymentPort`（`packages/core/src/hosted/payment-port.ts`）：

| 契约方法 | 已具备的语义 |
|---|---|
| `createOrder` | 返回 `checkoutUrl`（设置页已会渲染"前往支付"链接），幂等订单 |
| `queryOrder` | 用户主动查单，confirmed 时携带已验签支付事实 |
| `requestRefund` / `queryRefund` | 退款提交与确认，幂等 refundId |
| `verifyWebhook` | rawBody + timestamp + signature 验签后产出不可变支付事实 |

服务端配套已完整：订单状态机（created/pending/paid/closed）、`providerCreateState` accepted/unknown、
对账（none/needs-review/refund-required）、`/api/webhooks/payment` 免 Origin 校验入口、
最小订单/退款账目与业务资料分开保存。当前装配的是 `UnconfiguredHostedPaymentAdapter`，下单返回不可用。
也可以通过 `HOSTED_PROVIDERS_MODULE` 以运营模块覆盖，但正式路径应是在 adapters 实现真实 provider。

**需要注意的适配缝**：webhook envelope 目前只有单个 `x-luoome-payment-timestamp` / `x-luoome-payment-signature` 头；
微信支付 V3 回调带 `Wechatpay-Timestamp/Nonce/Signature/Serial` 四个头，支付宝是表单内 `sign/sign_type`。
实现时要么扩展 envelope（透传全部签名头），要么在适配层把多头编码进现有两字段——前者更诚实，建议前者。

## 2. 候选方案对比

### 方案 A：个体工商户 + 微信/支付宝官方直连（推荐）

| 项 | 微信支付 Native（扫码） | 支付宝电脑网站支付 |
|---|---|---|
| 主体要求 | 个体工商户可 | 个体工商户可（投资类行业不开放） |
| 费率 | 0.6%～1%（按类目；服务商渠道可谈到 0.2%～0.38%） | 0.6%（签约 1 年） |
| 结算 | T+1 到结算账户 | 交易成功实时到支付宝账户 |
| 申请费 | 免费；审核 1～2 个工作日 | 免费；审核 1～2 个工作日 + 签约 1～2 个工作日 |
| 网站要求 | 实际审核需 ICP 备案域名 | **硬性要求 ICP 备案**，个体户备案主体须与支付宝账户主体一致 |
| 对 luoome 的映射 | `createOrder` → `code_url` 生成二维码页；`queryOrder`/退款/验签均有 V3 API | `createOrder` → page.pay 跳转 URL；异步 notify 验签 |

49 元/单的手续费约 0.29 元，可忽略。Native 扫码不需要公众号和微信认证年费，是最简接入形态。
风险点：经营类目选择——"投资类"在支付宝侧不可申请；应按"软件/信息服务"类目进件，
定价页文案继续坚守"工具和数据服务"，不碰荐股表述（与定价 PRD 的纪律一致）。

### 方案 B：支付服务商二级商户（PayJS / 虎皮椒 / Xorpay / 小金商户助手等）

- 优势：个人身份证即可进件，当天～数日开通，有成熟 API 和异步回调。
- 费率：官方 0.6% 之上平台再抽 1%～6%，多数还有开户费（50～500 元）或月费。
- 风险（按严重性排序）：
  1. **跑路风险**：服务商数以万计，良莠不齐，需核查清算协会备案、ICP、是否直连结算；
  2. **执照混用**：部分平台（如虎皮椒被质疑的案例）给用户挂靠陌生人的营业执照，登记经营者与实际经营者承担连带法律和税务责任；
  3. 微信小微商户通道**仅限线下行业**，线上虚拟服务/订阅不在支持范围，被风控识别即冻结。
- 结论：只作为"本周就要收第一笔钱"的过渡，不作为 luoome 的正式通道；选了就必须核查清算协会备案与资金直连结算。

### 方案 C：境外 MoR / Stripe / Lemon Squeezy

- 面向全球 SaaS 的常规解法，但 luoome 用户是境内 A 股散户，付款习惯是微信/支付宝扫码；
  信用卡 + 美元结算的转化率损失远大于费率差（境外 2.9%+ 甚至 5%+ vs 国内 0.6%）。
- 还需要境外主体（注册 + 年审约 2000～3500 元/首年）。结论：不适用。

### 方案 D：个人收款码 / 转账

- 无异步通知、无订单关单、无退款接口；商业收款触发风控冻结（最长 180 天）；税务风险。
- 结论：不可行，连过渡都不建议——邀请期不收钱也比冻结强。

## 3. 硬性前置条件（与支付本身同等重要）

| 前置 | 要求 | 周期 | 成本 |
|---|---|---|---|
| 营业执照 | 个体工商户即可（微信/支付宝/备案主体三处一致） | 3～7 天 | 自行办理≈0，代办数百元 |
| 域名 + ICP 备案 | 支付宝硬性要求；微信实际审核需要；当前 IP+HTTP 不可用 | 2～4 周（腾讯云管局审核） | 域名约 50 元/年，备案免费 |
| HTTPS | webhook 必须公网可达且可信；compose 已内置 Caddy，备案后切 `HOSTED_DOMAIN` 即可 | 随备案 | 0 |
| 对公/结算账户 | 个体户可用经营者个人银行卡结算 | 随进件 | 0 |

## 4. 合规矩线

1. **经营性 ICP 许可证**：《互联网信息服务管理办法》要求经营性互联网信息服务（含会员收费）办理 ICP 许可证，
   无证经营可处没收所得 + 3～5 倍罚款（无所得或不足 5 万处 10 万～100 万罚款），情节严重责令关站。
   实务中大量小微 SaaS 只做了 ICP 备案未被追责，但这是真实存在的监管风险，且 ICP 许可证要求企业主体（个体户不可办）+ 3 名员工社保。
   **建议**：邀请期控制规模（现有 `HOSTED_REGISTRATION_LIMIT=30` 正好），收费正式化前评估是否升级为公司主体并办证；此风险必须在上线决策中显式记录。
2. **投顾资质**：支付类目、购买页、通知文案全线坚守"工具/数据服务"，不出现荐股、收益承诺——既是定价纪律，也是进件审核通过的前提。
3. **税务**：个体户收款即经营收入，按小规模纳税人申报；月流水低时税负极小，但必须申报。

## 5. 推荐路线

```
阶段 0（现在）        邀请期只跑 7 天试用，不收费；支付保持"未装配"诚实状态
阶段 1（2～4 周）     办个体户执照 → 买域名 → 腾讯云 ICP 备案 → Caddy 切 HTTPS 域名
阶段 2（备案后 1 周） 支付宝电脑网站支付进件 + 实现 AlipayPaymentAdapter（沙箱先行）
阶段 3（并行）        微信 Native 进件 + 实现 WeChatPaymentAdapter（V3，扫码码页）
阶段 4                双渠道上线，真实退款演练，对账 needs-review 流程走通，才开放正式收费
```

### 工程落地清单（每个 provider 约 2～4 个工作日）

- `packages/adapters/src/hosted/` 新增 `alipay-payment.ts` / `wechat-payment.ts`，实现 `HostedPaymentPort` 全方法；
  密钥走 secret 文件（沿用 SMTP/auth 的 `*_FILE` 约定），不写入套餐或仓库。
- 扩展 webhook envelope 透传完整签名头（微信四头 / 支付宝表单 sign），保持"验签通过才算事实"的现有语义。
- 微信 Native 的 `checkoutUrl` 是 `code_url`（weixin:// 协议），设置页需要渲染二维码而非跳转链接——
  这是前端唯一的产品改动点。
- 环境变量与运行手册同步：`HOSTED_PAYMENT_PROVIDER`、`WECHATPAY_*` / `ALIPAY_*` 配置组；
  未配置时维持现有的明确不可用行为。
- 测试：fixture 契约测试保留；真实渠道用 1 分钱真实单 + 退款走通验收，证据记入运行手册。
