# DSH 插件平台详细研究与验证计划

> 状态：研究规划与实施依据；首批受控开发切片通过，完整研究门槛尚未全部完成，逐项状态见 1.1。
> 创建：2026-10-20；验证状态更新：2026-10-21。
> 设计依据：[Luoome × DSH 插件能力平台设计](./ddd/dsh-plugin-platform-design.md)。
> 开发安排：[任务拆分与线程边界](./dsh-plugin-platform-development-plan.md)；实验状态以实际交接证据更新，不因创建线程而算通过。
> 范围：保留 Luoome 前端和业务，通过 SDK + 原生 Cordis 插件接入 DSH；不使用 MCP、不 fork DSH。

## 1. 研究目标与当前结论

要验证的产品目标是：Luoome 可以把投资业务组织成插件，也可以组合经过评估的外部能力，形成不同 Agent 场景。仅证明 SDK 能返回一句话，不足以决定迁移。

设计阶段完成了现有 Chat、工具、草案确认、托管计量与租户生命周期核对，阅读固定 DSH 源码，并建立候选清单。设计交付时没有安装插件、启动 DSH、调用付费服务或执行下表实验；后续开发实验以各线程的实际证据更新，不能由候选清单推定兼容或性能结果。

| 当前证据 | 可得结论 | 尚不能推出的结论 |
|---|---|---|
| SDK 与 Cordis 的公开契约及实现 | 控制接口与原生能力扩展可以分开接入 | 任意 Cordis/DSH 插件都能直接用于 Luoome |
| Luoome 现有 callable、场景权限与草案包装 | 可复用业务定义，不必重写几十个工具 | 直接导出 registry 就能保留全部安全语义 |
| DSH SDK durable 通知路径 | 可获得持久消息、状态和子 Agent 通知 | 当前 SDK 已提供浏览器所需的实时文本增量 |
| SDK 启动使用 process.execPath | 宿主运行时会影响子进程 | Bun 中调用 SDK 必然启动兼容的 Node Runtime |
| 同进程原生插件与子 Agent 的作用域实现 | 插件是部署代码；子级需重新授权 | Cordis scope、不同 Session ID 自动构成租户隔离 |
| 官方网页/搜索组件、社区插件和成熟库的公开资料 | 有可研究的复用路线 | 候选已经通过兼容、成本、数据范围和质量验收 |

事实证据集中在[设计文档的上游索引](./ddd/dsh-plugin-platform-design.md#15-上游证据索引)。上述表格保留设计阶段证据；实施后的状态以下表为准，架构文档只描述已验证的开发路径。

## 2. 固定基线与证据产物

### 2.1 基线规则

本轮 DSH 源码审查固定到 `687f282e8625c6b8d11ff58211a90524be2e4317`，SDK manifest 为 `0.2.1-rc.2`。首批已验证同版本 npm 安装产物、Cordis `4.0.5` 与 Node `22.22.3`；完整性和审查范围见 [artifacts.json](../infra/dsh/artifacts.json)，不宣称其为最新稳定版。源码 engines 为 `^22.19.0 || >=24.0.0`。

Luoome 当前工作树含并行开发中的 hosted 改动。实验开始时记录 Luoome commit、相关未提交差异指纹与配置版本；禁止为了制造“干净基线”丢弃他人工作。对照组和试验组必须引用同一业务代码、数据和策略快照。

每次可复现实验至少记录：

- Luoome/DSH/插件精确版本、安装产物完整性、依赖锁、Node/Bun/操作系统版本。
- Profile 与工具清单哈希、场景/模型/费率配置版本、测试 fixture ID；不保存密钥或私人投资数据。
- 实验命令、开始结束时间、run/session/tool/provider-attempt 关联、预期与实际、退出码。
- 脱敏事件时间线、必要的前端观察、资源采样、费用回执状态和失败复现步骤。
- 结论分为通过、失败、受阻、未执行；失败不得改成“基本通过”，源码推断标注为推断。

建议实施阶段将小型脱敏 fixture、契约断言和复现脚本纳入对应包测试；原始运行日志留在受控实验目录。评估报告只保留最小证据和引用。本文不预建空目录、样板工程或重复清单系统。

### 2.2 先模拟、再真实调用

先使用受控模型流、行情响应、搜索响应和故障注入验证协议；通过后再以测试租户和明确预算执行少量真实请求。模拟结果只能证明契约，不能证明模型研究质量、供应商兼容或真实费用。

真实请求启动前必须具备凭据装配、请求前预算准入和可核对的消费记录。R05 的模型准入最小切片因此是首次真实调用的前置条件，不等待托管验收末期才补计费。外部插件若收费，还须先完成对应的费用控制切片。

## 3. 插件候选调查

### 3.1 分类与评估方式

“外部能力”包含官方生态组件、社区原生插件和成熟库的薄适配，三者分别评估。SDK/库不是可直接装载的 DSH 插件；只有 MCP 接口的服务不进入本轮方案。支持 MCP 的产品如同时有原生 HTTP/SDK，可只评估后者。

准入先看必需条件：可固定产物与许可证、可在 headless 模式启动、依赖范围可解释、工具/网络/文件/凭据可约束、取消与清理可观察、付费调用可计量。任一必需条件无法满足，就不能靠综合评分进入托管组合。

在通过必需条件后比较维护证据、测试质量、输出质量、接入改动、资源与费用。存在 tests 目录或 README 声明不等于测试已通过；GitHub stars 不作为成熟度结论。

## 5. 实验规格

### R00：产物与最小 Profile

**输入**：固定上游源码、拟使用 SDK/runtime 发布物、插件清单；无个人配置的临时环境。

**步骤**：核对包实际发布版本、exports/依赖/engines 与源码差异；审查 lifecycle/install scripts、原生依赖与许可；固定锁和完整性。构建没有 MCP、Shell、任意文件写入、插件管理、额外日志上传和无关 UI 的 Profile，分别检查合并后的配置与运行时实际工具库存。

**输出/通过条件**：可从锁定产物重复安装和启动；配置/库存与批准清单一致；Node、Profile、产物哈希可记录。stdout 只含 SDK 协议，诊断去 stderr。

**失败处理**：发布物与源码不对应则重新冻结可验证组合；无法构造受限组合则阻止托管试点。不得改用完整 coding bundle 掩盖缺失依赖。

### R01：启动、控制与实例管理

**输入**：R00 组合；Bun 直接 SDK 与独立 Node Host 两种实验入口；可控模型 stub。

**步骤**：记录宿主和子进程实际 executable/version/PID；验证启动、握手、发送/恢复会话、close、父进程退出及启动失败。测试 cwd/env/home 与标准流边界、并发容量耗尽、空闲回收及健康探针；证明 Node 路径不加载 bun:sqlite。

**输出/通过条件**：明确的进程拓扑与生命周期记录；关闭后没有遗留执行者；实例达到上限时拒绝或排队且有界。Node Host 作为可复现基线，Bun 只有在相同用例通过后才可作为简化备选。

**失败处理**：Bun 不兼容保留 Node Host，不引入未经证实的 SDK 参数强行选 Node；连 Node 基线也不稳定则暂停业务接线，保留现有 Runtime。

### R02：业务插件与 Gateway

**输入**：现有 Chat callable map；fetch_quote 和一个草案工具；包含联合类型、可选值、嵌套数组、边界数值和失败结果的 schema fixture。

**步骤**：从本轮 callable 派生声明而非全 registry；注册到 DSH 并调用 Gateway。覆盖正常结果、output.error、__luoomeDraft、非法输入、超大输出和工具超时；同名冲突、manifest 不一致、未注册工具、错误 audience、过期/撤销 scope、错误 Tenant/generation/account 都应拒绝。验证 DSH canonical output 和失败状态准确保留业务含义。

**输出/通过条件**：schema 转换表、请求/回执协议和契约测试；真实调用沿既有工具层，write/Advice 返回草案；模型填写身份不能改变执行主体。原工具测试不因桥接而重写或放宽。

**失败处理**：无法表达的 schema 使用明确的协议投影或限制首期工具范围；不静默删字段。工具授权与草案语义无法保留则不继续真实写入旅程。

### R03：外部通用插件与可组合性

**输入**：候选矩阵、受控网页/搜索响应、批准的公开来源；实际发布物在 R00 冻结。

**步骤**：先加载官方 fetch-only 组合，与 market 插件完成同一研究；验证无需 DSH UI、无 MCP、没有重复实现其 handler。检查其真实注册、timeout policy、取消、网络出口、输出清理、工具失败及资源释放；同源/跨源跳转、私网/DNS 变化、过大/慢响应和主动脚本页面均用受控 fixture。再比较官方 Exa 和社区搜索：列出 UI/服务依赖、隐式模型/API 调用、凭据和持久状态，验证能否仅配置后端服务。

**输出/通过条件**：每个候选有独立准入记录；至少一个通用能力与业务插件共存，增减只改组合/授权配置，桥接无针对候选业务逻辑的分支。原生工具照常在 DSH 执行，Luoome 仍能限制本轮使用、外发与费用。

**失败处理**：候选依赖 UI 或不受控出口则拒绝/隔离；可选择另一个通过的原生组件。必要时薄适配库，但报告必须披露适配量，不能将其算作“零改造安装成功”。社区候选未通过不阻塞使用已通过的官方能力。

### R04：实时事件与用户可见流式

**输入**：具有可控首块延迟、工具调用和尾部 usage 的模型流；当前 Web Chat 和 hosted 两处缓冲路径。

**步骤**：记录 provider chunk、DSH transient event、SDK durable notification、Bun 发送、浏览器接收的单调时钟时间线。通过插件侧通道送增量，验证与 SDK 最终消息按 message/attempt/turn 对齐。覆盖工具前后文本、重试、断线重连、重复/乱序事件、背压、超大输出和未知事件；检查 ChatMessage.parts 上限和脱敏。再在真实浏览器验收现有 Chat 卡片与确认卡。

**输出/通过条件**：浏览器在模型完成前收到真实文本和工具进度；最终全文不重复追加；工具失败不显示成功；隐藏推理不原样展示。移除全量缓冲后，计量、收尾持久化与租约仍正确。

**失败处理**：可保留明确标识的非流式研究演示，但 AC05 未通过，不能宣称原 Chat 体验已完成迁移；继续研究事件桥而非将最终全文切片伪造实时流。

### R05：模型与插件费用

**输入**：现有 hosted ledger/预占/恢复契约、供应商 usage fixture；固定模型及费率快照；候选的付费请求清单。

**步骤**：先让 DSH 经过受控模型代理，证明请求前预占、成功结算、预算不足拒绝。再触发重试、compaction、辅助标题/总结等实际启用的隐式调用；R12 启用时补齐后代调用。核对 uncached input/cache read/cache write/output 的口径；模拟并发争抢余额、响应丢失、usage 缺失、重定向、断流、取消及进程崩溃。搜索、embedding 或插件内模型请求按独立 attempt 对账，检查绕过代理的直接出口被拒绝。

**输出/通过条件**：每个发送到收费供应商的 attempt 均有先行准入和回执关联；没有将未知费用当零；并行总预占不超限；用户界面区分估算、已确认和未知。取消不能撤回供应商已发生的成本。

**失败处理**：未覆盖的付费插件/功能停用；若主模型请求无法完全受控，不开放真实托管流量。只有证明全覆盖后，才比较 hook 方案是否能替代代理。

### R06：草案确认与后续上下文

**输入**：现有可确认旅程，优先 Watchlist 或策略草案；服务端保存的输入和已有 settle_chat_draft。

**步骤**：生成草案后结束 run；用户确认、拒绝、重复点击、另一账户确认、篡改客户端输入；检查只执行保存的输入及既有原子认领。模拟业务工具失败、确认响应丢失和新一轮启动；把权威回执送入 DSH，核对后续回答不继续假定未执行或成功。用户文字“我已确认”不能生成真实回执。

**输出/通过条件**：未确认无写入；重复确认不重复执行；成功/失败真实结果只补充为事实，不再次调用目标工具。区分现有实体规则与新增草案策略：当前协议没有通用 TTL/所有实体版本检查，不能把不存在的保证写进结论。

**失败处理**：回执同步不可靠时保持 Luoome 历史权威，通过明确重建上下文继续；不得修改 DSH 私有日志或放开自动确认。需要新 TTL/版本控制则单独形成设计变更。

### R07：会话、输入送达与调用去重

**输入**：一 conversation 多轮请求、R06 确认回执、DSH 持久 Session；待评估的 RuntimeBinding/delivery 记录。

**步骤**：两个浏览器并发提交同会话，确保串行/冲突行为确定；测试首次创建、续聊、服务重启后 resume。分别在“保存用户消息后”“enqueue 已接受但回包前”“工具已执行但回包前”“回执已保存但游标未更新”崩溃。对相同 callId 重发原请求和变更 input/tool/manifest 的请求，验证只前者可重用已确认回执。

**输出/通过条件**：不每轮重复追加全部历史；不丢确认事实；相同身份不会重复产生业务副作用。模糊 enqueue/执行结果能查明或标为 unresolved，不能宣称 SDK 天然 exactly-once。明确哪些记录必须持久化，并遵守 tools 入口、双仓储与迁移约束。

**失败处理**：缺乏可信核对手段时停止自动续跑，提示执行中断并从可信历史开始新 run；不盲目重发、更换 ID 或自动改用旧 Runtime 重跑。

### R08：取消与故障窗口

**输入**：运行中的文本流、慢工具、已发送 provider 请求、R07 持久记录；可注入数据库/进程故障的实验环境。

**步骤**：分别执行浏览器断开、用户停止、Bun/Host/DSH 意外退出、工具拒绝取消及数据库写失败。SDK 没有单轮取消时关闭专属实例，核对目标影响范围、实际 PID 退出、插件后台工作和 provider 回执。使 onFinish 抛错/超时，验证有限收尾、租约释放与启动恢复，不无限等待数据库。

**输出/通过条件**：撤销后不发起新调用；停止不伤及其它会话；只有确认排空才释放对应活动屏障。部分文本、未保存草案、执行终态与未知费用分别表达；DB 无法记录失败时可由既存运行记录识别未完成 run。

**失败处理**：执行者是否停止不明则进入 unresolved 并隔离实例；禁止假报 cancelled 或提前清目录。必须完善收尾和恢复后才能灰度。

### R09：隔离、删除、恢复与配置变化

**输入**：两个独立测试 Tenant、同 Tenant 两个账户/会话、不同 generation、各自测试文件与日志、备份样本。

**步骤**：交换/伪造 Session ID、run ID、凭证和事件订阅；尝试读取另一租户目录、日志与工具数据。检查白名单外工具、内网/metadata/本机管理端口、DNS/重定向绕过与错误日志泄露。执行权益策略切换、权限撤销、模型/行情配置更新、Tenant 删除及从旧备份恢复，验证在途 run 保持原快照但撤销立即生效，新 run 使用新配置。

**输出/通过条件**：隔离由服务端授权和进程/目录/出口控制提供；Session ID 不是通行证。删除覆盖新建的 DSH_HOME、附件、日志、凭证和活动执行；恢复应用最新删除 ledger，不复活旧执行或再次付费。行情插件通过当前工具上下文获得配置，不缓存永久旧实例。

**失败处理**：找到跨租户读取/执行或删除后仍能调用即阻断灰度；不通过共享高权限凭据或只换 Session ID 规避问题。

### R10：插件、场景与版本切换

**输入**：同能力两份固定插件/配置版本，场景 A/B，不兼容依赖、缺少 service、重名工具和启动异常 fixture。

**步骤**：验证注册/失败诊断/清理；测试同会话从广能力场景变到窄场景，旧凭证及工具绑定是否撤销。旧组合执行中发布新组合，排空后路由新请求；做启动探针失败回退、Session 格式不兼容与后台任务未退出演练。审查第三方升级差异及 install scripts 变化。

**输出/通过条件**：在途 run 固定组合；配置变更后新 run 使用新版本；同名冲突不静默覆盖；旧能力无法凭历史描述继续调用。若可靠更新 Agent 作用域不可行，明确重建实例/Session 的方案和成本。

**失败处理**：不强行热更新所有会话。无法恢复旧格式则让旧实例完成并保留日志，再以可信历史建立新 Session；不自动降级读取/覆盖不兼容持久数据。

### R11：质量、延迟、资源与费用对照

**输入**：现有 AISDKAgentRuntime 与 DSH 两组，固定任务、工具响应、模型、最大输出、权限与数据时间；具体模型取现有配置，不硬编码未经验证的型号。

**步骤**：先冻结评审 rubric，再测现有基线；模拟合同场景与真实模型任务分开。记录冷/热启动、首个真实浏览器文本、首个工具、总时长、进程 RSS/数量、并发队列、调用/重试数、输入输出/cache tokens、实际或未知成本。评审事实准确、来源可追溯、缺失与时点说明、风险/反证、确认语义及错误处理。

**输出/通过条件**：形成可复现对照表，分别标明模型随机性、插件增益与 Runtime 开销。安全/业务不变量零违反；质量与性能容忍线在看 DSH 结果前基于现有基线和产品目标冻结，不能事后选择有利指标。少量样本仅报告范围/中位数，不把不可靠的 p95 当容量承诺。

**失败处理**：质量退化、成本不可控或资源不支持预期并发时保留原 Runtime 默认；可只开放获益场景。不能以“插件更多”替代投资研究质量证据。

### R12：多 Agent 专项

**输入**：已通过单 Agent 门槛的组合；父 Agent、两个不同职责子 Agent 和一层后代；共享原子预算。

**步骤**：对子级重新签发能力范围/额度，禁止扩大父级权限或选择更高权限 preset；验证 DSH 默认不继承父级局部限制的路径确被补上。测试最大深度/数量/并发、子级秘密和兄弟任务数据、后台子级失败、父级 idle 后仍活动、父级取消、服务重启，以及子级重试/压缩的费用。

**输出/通过条件**：父子层级、工具与费用可关联；有效权限逐级收窄；总预算不能被分支复制放大；完成等待所需后代排空。比较 SDK run 的 next-idle 行为与 session/wait/子任务生命周期契约，不仅依据父级返回文本判完成。

**失败处理**：保留单 Agent；不因父级结束而释放仍运行后代的租约/预算。共享进程达不到隔离目标时研究受控独立进程后端，再做同一组验收。

### R13：灰度与回退演练

**输入**：AC01–AC11 的证据引用、批准组合、预算/容量与停止条件、原 Runtime 可用版本。

**步骤**：先仅测试租户，后按部署配置开小范围新流量；演练故障停止接单、排空、回退新请求、旧 Session 处理和费用核对。检查运行日志可诊断且脱敏，运维可查询版本、实例、活动任务及 unknown 回执。

**输出/通过条件**：每个验收项明确通过证据、评审人/角色与遗留限制；回退不重放旧任务、不双写、不重复付费。通过后才更新维护文档中的当前行为，多 Agent 仍独立受 AC12 约束。

**失败处理**：修复失败项或缩小试点功能后重验相关路径；不跳过授权、确认、计量和隔离门槛。

## 6. 实施波次与可交付切片

| 波次 | 工作与依赖 | 可评审产物 | 停止条件 |
|---|---|---|---|
| S0：冻结与契约 | R00、R01；同步冻结 R11 现有基线 | 可重复启动记录、最小 Profile、版本锁、进程图、协议样本 | 无法可靠启动或移除非必要高权限能力 |
| S1：双插件研究闭环 | R02 + R03 官方 fetch；R04；先完成 R05 最小计费切片 | 原 Web Chat → DSH → 行情 + 通用网页 → 来源回答；真实增量与费用关联 | 任一真实请求绕过授权/预算；仅最终全文伪装流式 |
| S2：有状态业务闭环 | R06、R07；R08 基础故障；R03 社区比较可并行 | 一条现有草案确认旅程、下一轮真实回执、重启与去重结果 | 未确认写入、重复执行或模糊状态盲目重跑 |
| S3：托管与组合发布 | 完成 R05/R08/R09/R10，再做 R11/R13 | 全部单 Agent 验收报告、容量建议、发布/回退操作步骤 | AC01–AC11 任一关键门槛未通过 |
| S4：多 Agent 与更多能力域 | R12；逐域扩展 strategy/portfolio/watch/review | 一条可比较的多 Agent 研究旅程及 AC12 证据 | 子级越权、预算放大、父级提前完成 |

S1 必须同时包含自研业务插件和一个外部通用插件，否则未验证用户提出的组合目标。S2/S3 不以接入更多候选数量为目标；先使已有链路可恢复、可计量、可运营。

工作可按 Runtime、Tools/Web、Hosted、Plugin 四个责任面并行，但跨面协议先冻结。共享的 chat.ts、hosted-providers.ts、hosted-meter.ts、server.ts 同一时间由一个实施切片负责，避免并行重写。实际代码范围以仓库最新状态重新核对。

在 S0 结束、关键版本及启动不确定性消除后再估算人日；每个切片用通过条件控制完成，不以未经实测的固定上线日期承诺交付。

## 7. 对照样本与验收记录

建议先冻结 12 类任务，每类在相同配置下至少 3 次独立运行；这是计划样本量，不是已完成结果。真实调用受总实验预算限制，记录未完成样本，不在预算耗尽后继续自动重试。

| 样本组 | 场景 | 核心判断 |
|---|---|---|
| 行情事实 | 单股票行情；代码歧义；行情缺失/过期 | 主体、时间、缺失说明正确，不编造数据 |
| 通用研究 | 网页证据；来源冲突；网页注入/越权诱导 | 区分证据和指令，保留来源、反证与工具限制 |
| 业务确认 | 创建草案；拒绝/重复确认；确认后追问 | 未确认无执行，回执准确，后续上下文一致 |
| 运行故障 | 预算不足；慢工具/取消；中断恢复 | 不超额、不伪造成功、不重复付费/写入 |

网页、工具、确认和故障用例优先采用合成数据；真实行情与网页另保留时间快照。对照不是把同一真实写入任务同时交给两套 Runtime。只有研究性的隔离调用才可以分别计费对照，并明确实验成本。

结果模板：`实验 ID / 版本与配置哈希 / fixture / 命令 / 预期 / 实际 / 证据 / 成本状态 / 结论 / 待办`。发布评审另维护 AC01–AC12 到实验报告的映射，不能只有截图或“本地看起来正常”。

## 8. 决策记录与下一步

| 决策 | 当前建议 | 定案所需证据 |
|---|---|---|
| 启动拓扑 | Node Host + DSH 子进程 + Bun Gateway | R00/R01 |
| 首个生态能力 | 官方 fetch-only；社区搜索作为比较候选 | R03/R05/R09 |
| 工具拆包粒度 | 一个桥接包内按域模块化，后续按独立发布需求拆包 | R02/R03/R10 |

| 真实流式 | 原生事件桥 + SDK 持久事实校正 | R04/R08 |
| 持久恢复 | Luoome 保存可信绑定/送达记录，DSH 使用公开恢复接口 | R06/R07/R08 |
| 场景切换 | 每轮撤销并重建能力绑定，必要时重建实例 | R10 |
| 默认迁移与容量 | 保留现有 Runtime，测量后决定 | R11/R13 |
| 多 Agent 开放 | 单 Agent 全部门槛之后 | R12 |
