# A 股交易作战室：全市场题材轮动与核心股跟踪

## Problem Statement

盘中离开屏幕一小时后，用户想知道哪个方向仍然强、哪个方向刚刚接力，以及各自该观察哪几只股票。现有看盘页能展示行业热力、领涨股和涨停梯队，但行业日涨幅榜可能仍由早盘冲高的方向占据。单看关注列表也容易错过跨行业的新题材。用户需要看到变化发生的时点，以及当时足以支持判断的证据。

## Solution

提供独立于账户与 Watchlist 的市场总览、板块追踪、成交分布三个视图。用户从全市场发现异动，进入题材核对上涨面与核心股，再点进个股查看角色依据。点击盘中事件，三个视图统一切换到该事件的历史时点，可一键返回最新快照。后台连续采集，浏览器关闭期间的盘面也能回看。

## User Stories

1. 作为看盘者，我希望打开作战室就看到沪深 A 股的覆盖和更新时间，以便判断眼前的数据代表何时、多少股票。
2. 作为看盘者，我希望对照指数、涨跌平家数与个股涨幅中位数，以便判断指数和多数个股表现是否一致。
3. 作为看盘者，我希望将累计成交额与昨日同时点比较，以便判断今天是否放量。
4. 作为看盘者，我希望看到封板、当前炸板家数及最高连板，以便判断短线情绪。
5. 作为看盘者，我希望切换行业与概念，以便看到跨行业的题材联动。
6. 作为看盘者，我希望在同一张榜上比较当日涨幅与近 5、15 分钟涨幅，并分别排序，以便发现刚刚接力或转弱的方向。
7. 作为看盘者，我希望对照多个题材的盘中走势，以便识别领先顺序何时改变。
8. 作为看盘者，我希望点开板块看到上涨家数、有效成分数、封板数和成交占比，以便区分单股拉升与多数成员走强。
9. 作为看盘者，我希望看到启动先锋、成交核心和高度标各自的入选依据，以便知道该用哪只股票观察哪种变化。
10. 作为看盘者，我希望从核心股查看所属题材和其他成员的表现，以便核对多个题材是否由同一只股票拉动。
11. 作为看盘者，我希望看到核心股出现、开板、换位和退出的时间，以便了解带头股票如何变化。
12. 作为看盘者，我希望看到窗口成交占比和较上一窗口的变化，以便发现交易正在向哪些方向集中。
13. 作为看盘者，我希望了解概念成分重叠、漏采和停牌如何影响统计，以便正确理解占比与排名。
14. 作为看盘者，我希望在异动原因或涨停原因中看到来源与关键词，以便区分供应商解读和行情事实。
15. 作为看盘者，我希望看到多股同步异动但尚待核实的方向，以便在概念榜收录前进一步研究。
16. 作为中途返回的看盘者，我希望按时间浏览扩散、分化和换位事件，以便迅速补看错过的盘面。
17. 作为复盘者，我希望点击事件后看到当时已知的榜单、成分与个股证据，以便还原当时的判断。
18. 作为复盘者，我希望从任意历史时点一键返回最新盘面，以便继续盘中观察。
19. 作为移动端用户，我希望能从榜单直接进入所选板块与个股，再回到原时点，以便在小屏幕上完成同一条看盘路径。

## Implementation Decisions

- 身份全集来自 StockUniverse 的沪深 A 股范围。行情、涨停池与板块成分使用同一范围过滤。停牌、无有效报价、缺失字段分别记录；全市场宽度只在满足既有完整性契约时发布。
- 盘前同步扶摇公开的行业与概念目录、当前成分或按股批量反查结果。行业、概念及供应商代码分别标识；多对多关系保存首次观测、来源与历次变更。部分响应不可导致成员集体退出。
- 交易时段由后台采集共享快照。页面刷新读取已发布的同一批次，跨页读取不重复采集。记录来源、行情时间（可缺）、抓取时间、覆盖、缺口。采集重试按批次去重，重启后保留已发布历史。
- 日涨幅相对前收，窗口涨幅比较窗口两端价格。窗口成交占比使用成分股累计成交额增量之和除以同期全市场去重成交额增量；环比以百分点表示。分母无效、窗口缺样本或跨午休出现不可比情形时显示缺失。概念间可重叠，不把占比加总为市场总量。
- 板块走势优先使用对应指数；成分上涨比例独立展示。持续走强同时参考相对市场表现、上涨面和成交占比。扩散、分化与换位规则及所用阈值可追溯，用盘中样本校准。单次排名抖动不重复发事件。
- 核心角色由可复现规则计算。启动先锋依据首次可核实的异动及随后扩散，成交核心看成交贡献与持续相对强度，高度标依赖可核验的连板事实。证据不足可空或并列。供应商只给涨停时间时按原口径展示。
- 关联当日异动关键词、可空的涨停原因和已知成分。未归类联动标为待核实；后续命名、成分更新和角色调整从当时可知时点生效。历史读取同时按行情时点和信息已可见时点截断。
- 复用行情网关、市场情绪、连板天梯及数据健康契约。来源接入放在 adapters，确定性计算放在零 IO 的 core，持久化通过 repository；workflow 通过 tools 编排。Web 经 tool 读取选定交易日与时点的快照、走势、榜单、事件和个股依据。后台写入和外部访问遵守显式 opt-in。
- 先形成已编目题材轮动、角色、成交分布和回放的完整链路，再扩展未归类联动与跨日主线。原型包含六个模拟时点，其间隔只服务于演示。生产窗口上线前实测完整采集耗时、时间字段、字段覆盖率和限流；分别公布可用窗口与延迟。

## Testing Decisions

- 主验收入口采用 Web 对外市场查询 API，沿用 Web server 测试、可控时钟、可替换数据源和 SQLite 内存库。以一段可重复输入的交易日驱动正常采集与读取，只断言用户能看到的结果。浏览器另走一遍桌面和手机的关键路径。
- 验收轮动：甲题材日涨幅仍领先但多数成分回落，乙题材日涨幅靠后而窗口放量扩散。两种排序、上涨分母、成交占比与入选理由应能解释差异。
- 验收回放：点击 10:15 事件只返回当时可知的成员、核心股、榜单和证据；10:30 收到的原因或换位不会出现在较早快照。返回最新后查看变化全过程。
- 验收统计与可靠性：重复成分、停牌、含北交所股票、漏页、行情过期、午休和断流都有明确结果；缺数不会变成零或产生新事件。重试、重启后同一事件仅出现一次。新增持久化契约沿用已有 Drizzle repository 合约测试。
- 真实交易时段验证采集延迟和覆盖。模拟数据用于验证规则与流转，不能证明服务端具备分钟级时效。

## Out of Scope

首期不含北交所、港美股、逐笔行情、真实交易指令、自动下单、账户仓位建议。成交分布展示成交集中度。供应商口径的主力净额需要另行取得可用数据源；盘后龙虎榜不用于填补盘中净额。历史回放范围从有可信采样的时点起算。

## Further Notes

现有扶摇全市场快照取数链路需补保留成交额，并核查分页完整性。现有默认缓存为五分钟，批次时间也不足以证明每只股票最后成交的时刻。扶摇的主力资金、高频动向和新增概念接口目前仅面向其客户端。可用公开目录差分记录首次发现时间。
