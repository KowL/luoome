## 1. 文档结论

luoome 要形成的闭环不是“AI 自动交易”，而是：

```text
发现值得研究的对象
  → 沉淀研究假设和证据
  → 用确定性规则持续观察
  → 在关键变化时提醒
  → 用户主动生成 Advice 并决策
  → 用交易、结果和后续行情复盘
  → 调整研究假设、Strategy、Watchlist 或提醒规则
```

闭环采用统一的 `Strategy + Watchlist + Portfolio` 产品语言。当前的 `Tactic`、
`StockGroup` 和 `StockPool` 是演进起点，不是需要永久保留给用户的最终概念：

| 用户问题 | luoome 对象 |
|---|---|
| 市场里有哪些股票？ | `StockUniverse` / `Stock` |
| 我用什么方法发现和判断机会？ | `Strategy` / `StrategyVersion` |
| 某次策略运行发现了什么？ | `StrategyRun` / `StrategyResult` / `StrategySignal` |
| 我在持续关注哪些股票？ | `Watchlist` / `WatchlistMember` / `WatchlistMemberSource` |
| 为什么关注它？ | 成员来源、`ResearchNote` / `StrategySignal` |
| 发生什么时提醒？ | `AlertPlan` / `AlertRule` |
| 刚才发生了什么？ | `WatchTrigger` / `StockEvent` |
| 我应该怎么判断？ | `Advice` |
| 我实际做了什么？ | `Trade` / `Holding` / `Account` |
| 后来结果如何？ | `AdviceOutcome` / `SignalObservation` / `Report` |

`Strategy` 是正式领域实体，统一承接当前战法和后续的选股、评分、信号、风控及评估定义。
`Watchlist` 是正式领域实体，统一承接手工关注、策略发现、AI 发现和持仓关联。策略负责
“为什么选、如何判断”，Watchlist 负责“哪些机会进入持续观察及其生命周期”。

`Portfolio` 是账户、持仓、交易和策略归因形成的组合读模型，首期不复制已有
`Account / Holding / Trade` 存储。是否在后续提升为可持久化的组合规划实体，由资产配置需求决定。

## 2. 产品定位

### 2.1 一句话定位

> 一个本地优先、证据可追溯、由用户掌握最终决策权的个人投资 advisor。

### 2.2 目标用户

- 同时管理持仓与候选股，需要减少信息切换的个人投资者。
- 有自己的选股或交易方法，希望把方法变成可观察、可复盘流程的用户。
- 希望 AI 帮助研究和组织证据，但不希望 AI 擅自交易的用户。

### 2.3 核心价值

- 把“看到信息”转化为“与我的关注和持仓有什么关系”。
- 把零散观点沉淀为可追溯的研究假设。
- 把盯盘从持续看行情变成少打扰、可解释的事件提醒。
- 把 Advice 和实际行动、后续结果关联起来，形成真实复盘。

## 3. 产品边界

### 3.1 必须坚持

- `Advice` 不等于 `trade`；任何建议、预警、报告或 Agent 都不能自动下单。
- 事实、观点、建议分层展示，缺失数据不能伪装成零值或确定结论。
- 重要结论保留证据、来源、数据截止时间、反证、风险和有效期。
- 自动化可以同步事实、运行策略、更新 Watchlist 和生成事实型报告；生成 Advice 必须由用户主动触发。
- 默认本地单用户，不建设云端跟单、策略订阅或多租户交易平台。

### 3.2 本总纲不承诺

- 券商自动交易与订单执行。
- 机构级量化回测、自动组合优化或高频交易平台。
- Agent 市场、策略市场及跨用户共享投资建议。
- 把 LLM 放入分钟级策略或提醒规则求值热路径。
- 用历史相关性包装确定性的未来收益。

## 4. 闭环的六个阶段

### 4.1 发现

入口包括：

- 用户搜索并加入 Watchlist；
- 持仓通过 portfolio source 进入系统 Watchlist；
- Strategy 运行产生候选、评分和信号；
- Agent 在受限候选全集内生成 Strategy 或 Watchlist 成员草案；
- 公司事件、市场简报和 Agent 研究提供新的研究线索。

输出必须是可审计的“候选对象及来源”，不能直接变成买入建议。

### 4.2 研究

股票研究档案聚合：

- 股票基础信息与规范行情；
- 当前持仓、历史交易；
- 所属 Watchlist 和成员来源；
- 当前研究假设、普通笔记、来源摘要；
- 公司事件、StrategySignal、WatchTrigger；
- 历史 Advice 及是否仍在有效期。

研究档案是读模型，不复制 `Stock`、`Holding` 或 `WatchTrigger`。

### 4.3 观察

`Strategy` 发现和评价机会，`Watchlist` 承接持续观察，`AlertPlan` 回答“何时提醒”：

```text
StrategyRun ──► Watchlist ──► AlertPlan ──► Watch Runner ──► WatchTrigger
候选与评分       机会生命周期      规则与冷却       确定性求值        可审计事实
```

策略刷新失败或空结果时保留 Watchlist 上一版策略来源快照并标记 `stale`。行情缺失或昨收缺失时规则结果为
`unknown`，不得猜测。

### 4.4 判断

用户从股票详情、预警、报告或对话中主动生成 `Advice`。Advice 至少包含：

- `buy / sell / hold / watch / avoid` 之一；
- 适用标的、周期和有效期；
- 核心论点、支持证据与反证；
- 风险、信心度、数据截止时间和免责声明。

Agent 可以多步调用只读工具组织证据，但最终仍必须落到统一 `Advice` 契约。

### 4.5 行动

用户在外部券商完成交易，再由手工录入或未来安全的导入能力写入 `Trade / Holding`。

- luoome 不提供交易 UI。
- 写入本地状态需要显式 write opt-in。
- 某笔交易可以关联当时的研究假设、Advice 或来源 StrategyVersion，但关联不是自动交易授权。

### 4.6 复盘

复盘分三层：

1. Advice 复盘：是否采纳、实际盈亏、同期基准表现。
2. 信号复盘：触发后 T+1/T+5 等真实行情表现与样本量。
3. 账户复盘：基于真实交易和现金流计算收益、回撤与集中风险。

系统可以提出“调整研究假设或规则”的草案；任何修改都由用户确认并形成新版本或新的配置。

## 5. 核心用户旅程

### 5.1 从一个想法到持续观察

1. 用户说“关注现金流稳定、刚走出平台的股票”。
2. Agent 说明可执行部分和当前缺失的数据维度。
3. 系统生成 Strategy、目标 Watchlist 和一套 AlertPlan 草案。
4. 用户确认后保存，系统运行一次试算。
5. 后续成员变化和规则触发进入观察中心。
6. 用户点开重要变化，补充研究假设或主动生成 Advice。

### 5.2 从持仓风险到复盘

1. 系统 Watchlist 的 portfolio 来源持续反映当前持仓。
2. 持仓 AlertPlan 监测成本阈值、价格变化、StrategySignal 或公司事件。
3. 触发后展示事实和数据状态，不直接给交易命令。
4. 用户按需生成持仓 Advice，并自行决定是否操作。
5. 用户录入实际交易，之后回填 AdviceOutcome。
6. 周报汇总事实、缺失项和待复盘对象。

## 6. 信息架构

Web 保持少量稳定入口：

- 仪表盘：今日变化、重要预警、最新报告、数据健康。
- 观察中心：Watchlist、成员来源与阶段、提醒方案和最近触发。
- 股票研究档案：事实、观点、建议、持仓与时间线。
- 持仓：账户、仓位、成本、风险和实际交易。
- 报告与复盘：开盘/收盘/周报、Advice 与信号后续表现。
- 对话：跨入口的研究和操作草案入口，不复制业务页面。
- 设置：数据源、模型、权限和运行状态。

## 7. 产品指标

首期不以收益率作为唯一成功指标，先衡量闭环是否真实工作：

| 维度 | 建议指标 |
|---|---|
| 可用性 | Strategy 与 Watchlist 同步成功率、Watch Runner 心跳完整率、关键数据 fresh 比例 |
| 降噪 | 每周触发数、冷却抑制数、无用反馈率、待处理积压 |
| 可解释 | 含有效证据和数据时间的触发/Advice 比例 |
| 研究沉淀 | 有当前 thesis 的重点股票比例、来源可验证的研究笔记比例 |
| 决策闭环 | AdviceOutcome 回填率、交易与研究依据关联率 |
| 复盘质量 | 有足够样本的信号比例、缺失数据明确披露率 |

不得用短期收益承诺、AI 调用次数或聊天轮数代替用户价值。

## 8. 分期

### Phase 0：收口现有能力

- 统一页面与文档术语，并确定 `Tactic → Strategy`、`StockGroup → Watchlist`、
  `WatchPlan → AlertPlan` 的兼容迁移。
- 建立统一 Watchlist，迁移现有分组成员、方案、触发与研究档案关系。
- 让 Agent 能从这些对象导航，并保持 draft-and-confirm。
- 补齐当前能力的状态、数据时间和失败提示。

### Phase 1：研究到判断

- 股票研究档案体验完整。
- 观察中心支持成员变化、待处理事项和按需 Advice。
- Agent 可完成跨工具研究，并输出可追溯 Advice。
- 报告可回到具体股票、事件、触发和研究笔记。

### Phase 2：真实复盘

- AdviceOutcome 与 SignalObservation 形成稳定统计。
- 交易关联研究假设、Advice 和来源 StrategyVersion。
- 周报给出行为模式和数据质量问题，不做因果夸大。
- 用户确认后可创建 Strategy、提醒规则或研究假设的新版本。

### Phase 3：策略研究扩展

只有在数据覆盖和真实需求具备后，再评估：

- 更丰富的基本面因子与评分；
- 严格时间切片的回测；
- 组合归因与现金流口径净值；
- 可移植的策略研究定义。

## 10. 验收原则

任一阶段立项时都必须给出可演示的端到端场景，并满足：

- 用户能知道系统用了哪些数据、截止到何时。
- 缺失或失败以 `unknown / unavailable / stale / partial` 明示。
- Agent、Web、CLI 和 MCP 复用同一 tool 契约。
- 写操作可确认、可审计；Advice 和交易之间没有自动路径。
- 新对象确有独立生命周期，不能由已有对象组合得到。
