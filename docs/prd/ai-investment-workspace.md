## 1. 产品定位与要解决的问题

**luoome 是一个与用户共同制定短线波段参与计划，并持续研究、跟踪和复盘的 AI 投资助手。**

目标用户没有稳定的机会来源，没有时间持续研究和有效盯盘，也缺少连续交易记录；收到重要提醒后，能够及时查看并自行操作。
用户不必先定义选股策略、搭建提醒规则或学会维护投研工作流，就应能获得一次完整的辅助决策体验。

核心旅程：**AI 研究并提出方向 → 双方讨论形成共识 → 系统筛选与跟踪机会 → 提醒用户决定行动 → 记录实际成交 → 回看依据与结果。**

首版要解决三个直接问题：

| 用户问题 | 产品应交付的结果 |
|---|---|
| 我该关注什么？ | 有取舍的参与方向，说明依据、反对理由、适用条件和与用户的关系 |
| 我没时间看，什么时候需要我决定？ | 已确认计划持续跟踪，仅在值得介入时提醒；能核对跟踪是否正常 |
| 当时怎么想、后来怎么做？ | 连续保存研究和决策过程，以用户确认的成交连接实际结果 |

首页始终围绕“持仓有没有需要处理的变化、有哪些参与方向值得讨论、已经确定的计划进展如何”组织内容。
AI 是首页主要交互方式，持仓、方向和计划是双方共同查看与讨论的内容。

## 3. 首版范围与完成定义

### 3.1 必须交付

- AI 主导的首页及三个工作区域，真实事实优先展示，支持部分失败和未完成状态。
- 全局提问、卡片内讨论、完整讨论视图，以及跨刷新和跨日接续。
- 有证据的参与方向提案、比较、反对意见、确认与修订。
- 用户近期意愿和双方共识的持久记录，区分草案和生效内容。
- 将共识连接候选筛选与后续跟踪，清晰反馈启动、失败、暂停和等待条件。
- 离开页面后的后台跟踪、真实手机通知和打开后的最新状态核验。
- 复用已有成交登记与复盘，减少重复输入，保持建议、反馈与成交的区别。

### 3.2 本期不做

- 自动下单、券商交易接管、自动跟单。
- 全面重做策略工作台、行情终端、研究资料库和账户绩效系统。
- 新建多 Agent 平台、策略市场或面向所有市场的选股服务。
- 首版强制接入券商导入、语音会话或原生 App。
- 用涨跌结果承诺 AI 胜率或收益；用聊天同意推断实际成交。

### 3.3 完整闭环与阶段交付

手机首页可以先交付试用，但只有“方向共议、持续跟踪、真实通知、实际记录”全部通过验收，才能称为本 PRD 核心闭环完成。
未接通真实通知时必须标明“仅可在应用内查看”，不能宣称用户离开页面后也会被及时提醒。

## 4. 核心用户旅程

### J01：第一次使用，没有方向

1. 首页说明助手能协助研究、跟踪与记录，询问本次优先事项。
2. 用户可以先讨论市场方向，不要求先完成整套账户和历史交易录入。
3. 助手在需要个性化仓位判断时，再收集缺少的账户信息；在事实不足时只给明确范围内的研究意见。
4. 系统给出候选方向、自己的倾向和原因；没有足够证据时说明限制并给出下一步。
5. 用户讨论并选择方向，查看简短共识草案后确认；系统反馈保存及后续任务状态。

新建账户默认现金为零不能代表用户真实没有资金。未完成登记必须明确展示，不能据此给出虚假的个性化结论。
首次必要信息按决策收集，包括已有持仓、可用资金、近期意愿和明确不能接受的情形；不重复询问已知信息。

### J02：日常打开首页

1. 先展示已有事实、截止时间与账户状态，再展示可用的 AI 摘要。
2. 助手指出优先处理事项，按持仓风险、待决策机会、普通进展排序。
3. 用户从某条内容追问；当前讨论主体以可见标签表示。
4. 讨论结束后，确认结果回到对应卡片；用户可以继续查看其它内容。

没有重要变化可以简短呈现，但只有检查已完成且数据合格时，才能说明“未发现达到提醒条件的变化”。

### J03：比较方向，形成共识

1. AI 提出最多 3 个方向，说明证据、风险、等待条件及优先顺序。
2. 用户表达“以 A 为主，B 继续观察，已有持仓优先”。
3. 系统解释这一选择将影响哪些研究与提醒，展示待确认的具体变化。
4. 用户确认后保存新共识，继续保留此前版本与讨论来源。
5. 系统按共识寻找候选并跟踪；每个候选解释与方向的关系，不将确认方向视为确认买入。

### J04：用户与 AI 有分歧

1. 用户提出参与某个机会，AI 明确表态并列出反对理由。
2. 展示已知风险、缺失证据、与当前计划的冲突，以及改变判断所需条件。
3. 用户可以继续质疑、决定等待、保留自己的选择或记录已经发生的成交。
4. 系统保存分歧，继续在可用数据范围内跟踪；不能伪造赞同，也不能因用户没有采纳而停止服务。
5. 复盘核对当初反对的具体风险是否发生，不能凭最终涨跌改写原判断。

### J05：收到提醒并行动

1. 后台根据有效计划检查条件，生成有证据的提醒并提交投递。
2. 手机通知说明对象、发生的变化与需要查看的事项，链接到确切主体。
3. 用户打开后先看到最新状态，并可查看触发当时的事实。
4. 已过时、失效或被替代的机会明确显示变化，不继续沿用原行动措辞。
5. 用户自行交易后选择记录实际成交，或选择继续观察、跳过。
6. 只有已确认的成交写入账本，随后重新核验受影响计划。

### J06：修改偏好，跨日继续讨论

用户可以说“最近谨慎一点”“先管理持仓，暂停新机会”。系统解释影响范围并生成变更草案。
确认后应用于未来研究与提醒；既有持仓的退出条件不会因偏好变化自动放宽。
次日继续讨论时引用当前共识与新证据，区分“仍沿用原判断”和“建议修改原判断”。

## 5. 首页信息架构与交互

### 5.1 页面层级

从上到下呈现：助手今日重点、持仓变化、参与方向、计划进展。需要立即查看的风险可在重点区域置顶，并链接唯一源卡片。
页面保留账户事实状态、数据时间与跟踪健康的轻量入口，不用运行日志占据首屏。
全局输入入口容易找到；手机端不得遮挡正文、风险或确认按钮。

助手开场摘要只概括已取得的事实和研究结果。正在研究时展示真实任务状态，不能使用虚构的进度百分比或声称已检查全部市场。

### 5.2 卡片要求

| 区域 | 首层内容 | 展开内容 | 主要动作 |
|---|---|---|---|
| 持仓变化 | 股票、重要变化、建议关注事项、事实时间 | 原计划、最新证据、反证、风险和未知项 | 讨论原因、查看计划、记录实际行动 |
| 参与方向 | 方向名称、倾向、核心依据、适用周期、主要风险 | 对比方向、证据来源、等待与放弃条件、账户适配限制 | 讨论、比较、加入共识、暂不考虑 |
| 计划进展 | 对象、当前阶段、等待或触发条件、监控状态 | 原版本、变更原因、触发历史、实际记录 | 讨论、复核、调整跟踪、记录成交 |

股票身份统一遵守现有名称/完整代码两行链接规范。
正式建议的反证、主要风险、有效期与必要免责声明必须保留，手机折叠布局不能隐藏影响决策的关键限制。

### 5.3 对话行为

- 从卡片发起时自动附带主体引用与版本，输入处显示“正在讨论……”并可切换。
- 简短追问就地展开，深入讨论可进入完整视图；桌面可采用并列布局，手机以单列完整视图为主。
- 各入口复用同一套会话与真实结果，不重复创建互相矛盾的助手状态。
- 切换到另一张卡时更新主体；用户返回原卡片时可接续原讨论。跨卡比较显式列出全部对象。
- 浏览器返回先退出当前讨论层级，再返回来源页；恢复原卡片展开状态和滚动位置。
- 历史会话保留可查入口；当前有效共识独立展示，不能靠用户翻聊天找结论。
- 草案未执行、执行中、成功和失败分别展示；模型只根据真实执行结果宣告完成。
- 停止当前回答、取消某次研究和暂停持续跟踪是不同操作；关闭讨论视图不会默默停掉后台任务，停止回答也不撤销已完成的写入。

## 6. 手机端专项要求

手机端优先设计，桌面扩展利用更大空间。

| 场景 | 首版行为与验收要求 |
|---|---|
| 小屏阅读 | 覆盖 360/390/430px；单列、无整页横向溢出，关键事实无需横向拖动大表格 |
| 触摸操作 | 主要点击区域至少 44px；不依赖 hover，确认与取消清晰区分 |
| 软键盘 | 输入与发送始终可见，适配动态视口和底部安全区域；输入法选字回车不误发送 |
| 长内容 | 先结论和关键风险，再按需展开证据；长股票代码、链接和中文换行正常 |
| 阅读中更新 | 用户上滑阅读历史时不强制滚回底部；有新内容时提供可点入口 |
| 返回与刷新 | 退出讨论回到来源位置；刷新能恢复已保存消息和结果，未发送输入的处理明确 |
| 切后台与弱网 | 回到前台读取真实任务和消息状态；失败可恢复，不自动重复写入或重复收费研究 |
| 账户变化 | 账户失效时停止私有请求；恢复后取回授权范围内的内容，换账户不残留上一账户数据 |
| 通知打开 | 进入时先通过入口鉴权（DSH basic auth + 启动 token），成功后回到目标；无权查看、对象删除、已过期均有明确说明 |
| 可访问性 | 控件有可读名称和焦点状态；文字放大至 200% 仍可操作；状态不只靠颜色区分 |

手机讨论视图应使用可用视口高度，不能沿用固定 500px 聊天区域。
通知到达验证、iOS Safari 与 Android Chrome 的键盘/后台返回需要真机记录；模拟视口仅验证布局。
未发送输入建议在同一账户的当前浏览器会话内恢复，切走或换账户即清除，不将私有草稿永久保存在跨账户共享存储中。

## 7. AI 研究与判断契约

### 7.1 参与方向的内容

每个方向需包含：机会类型与覆盖范围、当前适用理由、支持证据、反对证据和风险、等待条件、放弃条件、预计观察/参与周期、数据时间、复核条件，以及与用户当前状态的关系。
主题、板块或技术形态都可以成为方向，但仅列名称不构成完整提案。
AI 可以表达优先倾向，必须说明比较依据；不能为了数量凑出方向，也不能把置信度表述为盈利概率。

### 7.2 从方向到具体机会

确认方向后，系统根据方向内的可计算条件筛选候选，对需要解释的候选进行研究。
候选必须关联来源方向及版本；同股多方向命中时合并展示证据，不重复占用账户建议预算。
具体买卖建议与条件性安排复用 Advice、TradingPlan；方向共识不复制一套逐股仓位和退出规则。
单纯排序靠前不能直接触发买入提醒，必须满足当前有效计划和数据条件。

### 7.3 反对意见

反对回答至少给出：明确结论、对应事实、用户相关风险、未知项、改变判断的条件和可选下一步。
对于用户坚持的选择，记录其意见与系统分歧；超出账户或数据硬约束的方案仍不能被标为可执行。
证据缺失时可以解释判断边界，不能为了给答案补造价格、时间、事件或财务信息。

### 7.4 主动程度与执行

读事实和解释可以在当前授权范围内完成；生成正式 Advice 沿用现有确认入口。
长期研究、跟踪和外部通知由用户明确开启，页面展示研究范围、节奏与关闭入口。
确认参与方向不能隐式开启新的付费任务或通知渠道；确认卡应说明将执行哪些动作及必要消耗。
已授权任务范围内的日常运行不反复要求确认。变更范围、资金记录或权限时重新展示明确草案。
用户表达“我想买”不能转成成交，“已买入”仍须核对真实数量、价格、时间与是否已入账。

## 8. 参与共识、偏好与记录

以下是产品概念，具体实体名称与 schema 留给详细设计。

| 概念 | 内容 | 变更规则 |
|---|---|---|
| 长期约束 | 用户明确资金、风险和时间约束，以及现有账户硬约束 | 只有明确确认的修改才生效 |
| 近期意愿 | 更谨慎、优先持仓、暂停新机会等阶段选择 | 保存适用范围、开始时间、复核或结束条件 |
| 方向提案 | AI 提出的可比较方向及证据 | 尚未确认不代表当前参与计划 |
| 参与共识 | 主次方向、回避项、研究范围、复核条件及用户选择 | 版本化保存，引用讨论与证据；修改保留历史 |
| 跟踪状态 | 实际创建和运行的研究/监控任务 | 以真实任务结果为准，不由 AI 文本声明 |
| 决策记录 | 用户意见、系统分歧、明确反馈与实际成交引用 | 保留修订与来源，不推断未记录事实 |

### 8.1 共识状态与跟踪状态分开

共识从草案进入已确认，可被新版本替代、撤销或到期。证据发生变化时标记需要复核，保留原版依据。
跟踪单独呈现未开启、启动中、跟踪中、部分失败、已暂停、已结束。
“共识已保存、跟踪启动失败”是合法状态，需要重试入口，不能回报全部成功。

多个方向可同时存在，确认时明确主次和冲突处理；相互矛盾的行动要求不得静默合并。
多个标签页同时修改时应提示版本冲突，展示最新共识后再确认，不覆盖更新。

### 8.2 修订影响范围

方向变化默认影响后续候选研究；已有持仓与有效逐股计划须单独复核。
暂停新机会只停止对应研究/入场关注，不能默认关闭持仓风险跟踪。
退出、到期或替代的逐股计划遵守既有领域契约；本需求不更改硬有效期、账户指纹与预算规则。

### 8.3 记忆与历史

当前确认共识、账户事实和讨论主体优先进入上下文；历史聊天用于追溯，不能仅依赖最近若干条消息。
记忆摘要只能总结真实记录，重要数字、决策与来源必须可回查。用户纠正后，新摘要引用修订后的有效记录。
删除聊天和撤销共识是不同操作：删除前说明已确认共识仍保留；共识保留必要来源快照，不因聊天删除悄悄撤销跟踪。

## 9. 跟踪、通知、成交与复盘

### 9.1 持续跟踪

首页明确展示覆盖哪些持仓/候选、最近成功检查时间、未覆盖项及失败原因。
盘中依据已定义条件确定性求值；AI 负责解释与需要时的复核，不在每次报价更新时重新完整推理。
跟踪失败、数据缺失与无条件触发必须分别呈现；已知缺口不能被“正常盯盘”状态掩盖。

### 9.2 提醒内容与状态

提醒首层说明对象、变化、触发时间与建议查看事项；详情保留原条件、当前条件、风险、反证、有效期和卖出限制。
对同一未变化条件避免重复打扰，冷却、每日额度和优先级沿用现有规则。
提醒生成、渠道受理、可验证投递与用户查看分开记录；无法获得回执时明确未知，不声称用户已收到。
通知中的私有详情按用户设置呈现，用户能关闭渠道；设置变更后旧投递不得发往失效目的地。

### 9.3 实际记录

从讨论或提醒进入现有“登记实际成交/关联已有成交”界面，自动带入来源与股票。
实际数量、价格、时间与尚未入账确认必须来自用户或已核实记录，不能以建议值默认成交。
部分成交、分批退出和跳过均能表达；重复提交幂等，发生账本冲突要求刷新。
成交后现金与持仓按既有事务规则更新，受影响计划立即标记需核验，不能继续展示旧仓位下的可执行建议。

### 9.4 复盘

复盘连续展示：原方向与计划 → 系统判断及分歧 → 提醒 → 用户明确反馈与成交 → 已知后续事实。
市场事后表现、用户填报结果和实际账户绩效分别表达，不按同股或相近时间猜测归因。
无记录显示未知；没有完整证据时不宣称“避免了多少亏损”或“本次推荐成功”。

## 10. 数据依赖与降级

| 数据 | 最小要求 | 缺失时的产品行为 |
|---|---|---|
| 账户事实 | 现金、持仓数量/成本、成交、对账状态和合格估值 | 可继续一般研究，不提供精确仓位或可执行资金安排 |
| 个股行情 | 身份、交易日历、交易状态、来源和合格时间戳 | 不判断当前行动条件已满足，历史事实标明时间 |
| 日线/分钟线 | 前复权日线、成交量；盘中规则需要的实际数据粒度 | 缺什么就暂停对应条件判断，不伪造分钟走势 |
| 市场方向 | 指数、广度、成交活跃度、板块强弱及覆盖范围 | 缩小研究结论范围，不能用少量样本概括全市场 |
| 主题关联 | 可验证的主题/行业到股票关系及更新时间 | 可讨论板块事实，不假设有完整成分股名单 |
| 新闻/事件 | 真实来源、发布时间、股票关联和可回查证据 | 不编造催化；缺少覆盖时显式说明未核验相关风险 |
| 共识与历史 | 版本、确认结果、适用范围、来源与修订时间 | 保持草案或提示缺失，不猜测用户已同意 |
| 任务与投递 | 实际运行、失败、认领和投递结果 | 显示真实状态与恢复入口，不以生成文案代替任务成功 |

金融数据的事实时间与抓取时间分开；刷新页面不会让旧证据变成实时。
正式方向研究与行动建议的时效阈值必须在详细设计中按数据种类、交易时段和条件明确，并配置可重复测试。
新闻摘要工具不等于完整公告覆盖。涉及政策、公司事件或财务的判断需对应证据；没有时只讨论覆盖到的量价事实并披露限制。
财务 PIT 生产能力遵守现有门禁，不为首版量价机会伪造基本面依据。

## 11. 异常与恢复体验

| 情况 | 必须呈现与保留 |
|---|---|
| 首次无持仓、无共识 | 可先研究方向，分步补必要信息；不用空收益或空机会误导 |
| 只有部分事实可用 | 已有事实仍可看，逐项说明受影响的研究与跟踪 |
| AI 超时或不可用 | 保存用户问题与已完成事实，说明未完成研究；规则兜底不冒充研究结论 |
| 研究额度不足 | 明确未启动/未完成状态和原因，保留已有结果，不把它解释成没有机会 |
| 流式中断或主动取消 | 保存实际完成部分并标记中断；重进读取服务端状态后再提供恢复操作 |
| 草案提交后断网 | 查实际执行结果，不能直接重复执行；未知状态保持待核对 |
| 共识保存成功、任务失败 | 分别展示，针对失败任务恢复，不重复创建已成功部分 |
| 数据或计划已过期 | 可以查看历史，不能继续以当前行动卡展示；提供重新评估入口 |
| 提醒未送达 | 应用内仍可查看，显示可核实投递状态和失败原因 |
| 暂停或账户切换 | 清楚说明哪些服务停止、哪些记录保留；不承诺继续监控 |

## 12. 成功指标与质量要求

首版先验证是否完成用户任务，不用消息数、点击率或交易频率作为主要成功标准。

| 指标 | 统计口径与用途 |
|---|---|
| 核心旅程完成率 | 已开始方向讨论的用户中，完成共识确认并成功启动跟踪的比例；各步骤分别记录失败原因 |
| 带上下文讨论成功率 | 卡片发起且主体引用正确解析、回答引用正确对象的比例；失败与用户取消分开 |
| 共识连续性 | 跨日/刷新后能准确恢复有效共识的测试通过率，以及用户纠正错误记忆的次数 |
| 运行与提醒可靠性 | 计划应检查/实际检查、已生成/受理/可验证投递分别统计，并观察各段延迟 |
| 记录负担 | 登记一笔实际成交所需步骤与用户明确反馈；不要求用户补写系统已经知道的依据 |
| 判断质量 | 抽样检查证据存在性、时间、反证、风险、未知项与版本一致性；不将短期盈亏直接当作质量分 |

设计与性能初始目标：已有缓存事实的首页主内容在约定测试环境下 P95 不超过 2 秒；点击操作即时反馈，AI 未完成不阻塞事实查看。
该目标是待测量的产品预算，详细设计需明确设备、网络、样本量、冷启动和无缓存情况，不能宣称已有实测。
提醒需测量市场事实到求值、求值到渠道受理的延迟；渠道不提供到达回执时，最后一段只能靠真实手机测试记录，不能报告伪精确时延。
匿名使用统计只记录任务与状态，不上报私人持仓、聊天原文和密钥。

## 15. 技术实现约束与现有能力核查

### 15.1 约束

- 沿用 Hono + 原生 HTML/CSS/JS、现有 AI runtime、流式协议、SQLite 与账户级隔离。
- 分离会话状态与挂载视图，让首页、卡片与完整讨论共用能力，避免复制多套助手。
- 主体引用经服务端 tools 校验账户归属、版本和时效；前端文案不是可信市场或账户事实。
- 首页事实先返回，AI 解释按需或按已授权任务生成并保存；刷新不反复启动相同研究。
- 新领域契约遵循 surface/workflows → tools → core，以及 tools → db/adapters → core 的依赖方向。
- 新 repository 同时提供 drizzle/memory 与 contract tests，迁移幂等；不得直接复用通知偏好表存投资意愿。
- 已确认共识结构化保存，引用讨论和证据；检索不能仅依赖最近 20 条聊天。
- 真实写入遵循现有草案确认；成交走专用 Web 登记路径，trade 永不进入模型/MCP 通用工具面。
- 盘中条件确定性求值，AI 复核保留证据与版本，所有失败返回既有错误模型。
