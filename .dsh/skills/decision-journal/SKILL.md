# decision-journal

把用户的决策落到 DecisionReview。

## 流程

1. 确认事实底座：`mcp__luoome__get_analysis_context` 取当前事实包（持仓、成本、既有建议、行情）。取不到就用只读工具补，数字必须来自工具。
2. 整理决策四要素：
   - **决策**：买 / 卖 / 持有 / 减仓 / 加仓（用户没明说就不要替他定）；
   - **当时的依据**：他给出的理由，以及事实包里支持或反驳它的数字；
   - **假设**：这个决策成立的前提；
   - **失效条件**：什么情况出现就说明判断错了（价位、量能、事件、时间）。
3. `mcp__luoome__save_decision_review` 落库，保留上述四要素与 `dataAsOf`。
4. 回读确认落库结果，再向用户复述你记下的内容与失效条件。

## 边界

- 记录决策不等于给出建议，也不等于下单；这里没有成交能力。
- 用户的判断与事实冲突时，照实指出冲突并记录双方，不要把事实改写成支持决策的样子。
- 不要用事后信息补「当时应该知道」的理由；依据以决策时刻为准。
- 涉及金额与仓位时保留用户原始口径，不要自行换算或四舍五入到好看的数字。
